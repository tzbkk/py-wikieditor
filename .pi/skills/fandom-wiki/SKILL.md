# Fandom Wiki 页面拼接工作流

## 项目概况

这是一个 Fandom Wiki（擅长捉弄的高木同学 wiki）的自动化工具。Wiki 上已有 567 个页面（main 338 + Template 212 + Category 17），全部已下载到 `wiki_dump/` 目录。

**核心能力**：根据用户描述，从 Wiki 已有页面中提取数据，按模板拼接出新页面。

## 何时不用此技能

- **只想读单个页面** → 用 `wiki_read_page` 工具或 bash `cat wiki_dump/<page>.wiki`
- **要做繁简批量转换** → 用 slash commands `/wiki_convert_page`、`/wiki_convert_category` 等
- **要扫描分类页面** → 用 `/wiki_scan_category`
- **要批量修复链接** → 用 `/wiki_fix_links`
- **要更新分类引用** → 用 `/wiki_update_cat_refs`

## Wiki 数据结构

### 页面命名空间
- `wiki_dump/main/` — 338 个主页面（章节、剧集、角色、音乐等）
- `wiki_dump/Template/` — 212 个模板（信息模板、导航模板）
- `wiki_dump/index.json` — 全部页面的索引（标题 → 命名空间、文件路径、长度）

### 信息模板体系（页面骨架）

每个信息模板都有 `/doc` 子页面定义字段列表，有 `/preload` 子页面定义空白骨架。

| 模板名 | 用于 | 字段列表来源 | 页面数 |
|--------|------|-------------|--------|
| `{{章节资料}}` | 漫画章节页 | `Template:章节资料/doc` | 203 |
| `{{剧集信息}}` | 动画剧集页 | `Template:剧集信息/doc` | 39 |
| `{{卷资料}}` | 漫画卷页 | `Template:卷资料/doc` | 25 |
| `{{角色信息}}` | 角色页 | `Template:角色信息/doc` | 14 |
| `{{音乐信息}}` | 音乐页 | `Template:音乐信息/doc` | 19 |
| `{{动画资料}}` | 动画系列页 | `Template:动画资料/doc` | 5 |

### 导航模板（最关键的数据源）

导航模板定义了**完整的页面列表和分组关系**：

| 导航模板 | 包含内容 |
|---------|---------|
| `Template:擅长捉弄的高木同学章节导航` | 178 个漫画章节链接，按卷分组 |
| `Template:明天是星期六章节导航` | 53 个明天星期六章节，按卷分组（V1=1-24+番外, V2=25-52） |
| `Template:擅长捉弄的（原）高木同学章节导航` | 原高木漫画章节，按卷分组 |
| `Template:擅长捉弄的高木同学剧集导航` | 三季动画剧集链接 |
| `Template:卷导航` | 漫画卷列表 |
| `Template:角色导航` | 角色列表 |

**导航模板的分组行就是卷/系列归属**。例如 `明天是星期六章节导航` 中标注"第1卷"的那一行包含第1-24章+番外篇。

### 数据源交叉引用

| 要填充的字段 | 可能的数据来源 | 查找方法 |
|-------------|---------------|---------|
| 系列、卷数 | 导航模板的分组行 | 读导航模板，按分组行映射 |
| 上/下一章节/集/卷 | 导航模板的链接顺序 | 读导航模板，取前后链接 |
| 名称、日文名 | 剧集页面的 `=== '''片段标题''' ===` | 剧集页的 `== 片段 ==` 段落 |
| 摘要 | 剧集页面的片段描述 | 片段标题下方到下一个 `===` 之间的文字 |
| 出场角色 | 剧集页面的 `== 出场角色 ==` | 需根据页面类型筛选相关角色 |
| 动画对应集数 | 剧集页面的 `{{剧集信息\|漫画=}}` | 剧集信息模板中引用了章节名 |
| 图片 | 已有同类页面的图片命名规律 | 例如 `Doyobi_{N}.jpg`、`Volume {N} Doyōbi cover.png` |
| 章节数目 | 页面名中的数字 | 正则提取 |
| en: 链接 | 已有同类页面的英文链接规律 | 例如 `[[en:Ashita wa Doyōbi {N}]]` |

## 页面拼接工作流（核心）

**两轮交互，中间不停顿。**

用户说"帮我生成 XXX 类页面"时，按以下流程执行：

### 第一轮：用户下指令 → Pi 自动生成全部草稿

这一轮 Pi 连续执行，中途不问用户，最后一次性输出所有草稿。

**Phase A：理解需求**

确认以下信息：
- **页面类型**：什么类型的页面？（章节、剧集、角色、音乐等）
- **对应的模板**：用哪个信息模板？（查上表或从已有同类页面判断）
- **范围**：生成哪些页面？全部缺失的还是部分？

如果用户描述模糊，**先问清楚再动手**。如果用户描述已经足够清晰，直接进入 Phase B，不重复确认。

**Phase B：学模板（读已有页面）**

1. 从 `wiki_dump/index.json` 找到同类已有页面（2-3 个）
2. 读取它们的 `.wiki` 文件，提取：
   - 使用的模板名和字段填写方式
   - 页面整体结构（模板 → 正文段落 → 导航模板 → 分类）
   - 正文段落结构（如章节页是：开头句 → ==摘要== → ==出场角色== → 导航 → en链接 → Category）
3. 读取模板的 `/doc` 页面确认完整字段列表

**Phase C：确定缺失页面**

1. 读取对应的导航模板，提取完整的页面链接列表
2. 对照 `wiki_dump/index.json`，标记哪些已存在、哪些缺失
3. 只生成缺失的页面，**绝不覆盖已有页面**

**Phase D：提取数据（为每个字段找值）**

对模板中的每个字段，从 Wiki 已有内容中提取数据：

- 读取导航模板 → 系列归属、卷数、上/下章节导航
- 读取剧集页面 → 名称、日文名、摘要、角色、动画对应集数
- 按命名规律推断 → 图片文件名（如 `Doyobi_{N}.jpg`）、en 链接
- 调用 `wiki_check_files` 验证推断的图片是否已上传

无法从 Wiki 提取的字段用 `__待填__` 标记。

**Phase E：生成草稿并一次性输出**

为每个缺失页面生成 wikitext 草稿：
- 可自动填充的字段 → 填入提取的值
- 无法提取的字段 → 用 `__待填__` 标记
- 正文段落按已有页面的结构生成骨架

一次性输出以下内容，**不要中途停顿**：

```

使用模板：{{章节资料}}
```

### 第二轮：用户审核补充 → 确认上传

等待用户：
- 修改自动填充的内容（可能有错）
- 填写 `__待填__` 字段
- 可以一次填多个页面，也可以分批

用户说"上传"/"确认"/"可以了"后，使用 `wiki_save_page` 逐页上传（工具会弹出确认对话框，需再次确认）。

**上传前必须确认**：
1. 用户已明确说"上传"、"确认"、"可以了"等
2. 没有 `__待填__` 残留（除非用户明确允许）
3. wikitext 语法正确（模板、链接格式无误）

## 安全规则

1. **永远不要未经用户确认就上传** — 每次上传前必须得到明确许可
2. **永远不要覆盖已有页面** — 生成前检查 `index.json` 确认页面不存在
3. **不要猜测你不确定的数据** — 宁可标 `__待填__` 也不要填错误内容
4. **导航模板是权威数据源** — 页面列表、分卷关系以导航模板为准
5. **禁止修改 .env / config.json / credentials** — Extension 层 permission gate 自动拦截 edit/write/bash 三类工具的敏感路径访问

## 数据提取技巧

### 从导航模板提取页面列表和分组

导航模板是表格格式。`!` 行是组标题（卷名），`|` 行是该组内的链接列表。

```
!width="150px" bgcolor=#696969|[[明天星期六第1卷|第1卷]]
|...[[明天星期六第1章|第1章]] • [[明天星期六第2章|第2章]] ...
```

提取方法：
1. 按 `\n|-` 分割表格行
2. 以 `!` 开头的行提取组名（卷名）
3. 以 `|` 开头的行提取所有 `[[页面名|显示名]]` 链接
4. 按顺序配对：每个链接属于上一个 `!` 行定义的组

### 从剧集页面提取片段信息

剧集页面的 `== 片段 ==` 段落中，每个 `=== '''标题（日文名）''' ===` 就是一个片段。

结构：
```
=== '''中文名（{{Lj|日文名}}）''' ===
摘要文字...

=== '''下一个片段''' ===
...
```

提取方法：
1. 找到 `== 片段 ==` 或 `== 出场角色 ==`（片段在前，角色在后）
2. 用 `=== '''...''' ===` 分割出各个片段
3. 从片段标题提取中文名和日文名（`{{Lj|...}}`）
4. 从片段正文提取摘要
5. 从 `{{剧集信息|漫画=...}}` 中找哪个片段对应哪个章节（通过章节链接匹配）

### 从模板 /doc 页面提取字段定义

模板的 doc 页面（如 `Template:章节资料/doc`）中，`|field =` 格式列出了所有可用字段。

### 按命名规律推断

- 章节图片：观察已有同类页面的图片命名规律（如 `Doyobi_{N}.jpg`）
- en 链接：观察已有同类页面（如 `[[en:Ashita wa Doyōbi {N}]]`）
- 文件存在性：可用 `wiki_check_files` 工具验证图片文件是否已上传

## 常见页面类型速查

### 章节页面（明天星期六/漫画/原高木）
- 模板：`{{章节资料}}`
- 导航：各自的章节导航模板
- 数据源：剧集页面（有动画改编的）、导航模板（卷数、上下章）
- 典型结构：模板 → 开头句 → ==摘要== → ==出场角色== → 导航模板 → en链接 → Category

### 剧集页面
- 模板：`{{剧集信息}}`
- 导航：`{{擅长捉弄的高木同学剧集导航}}`
- 数据源：剧集列表页面、对应的漫画章节
- 典型结构：模板 → 简介 → ==出场角色== → ==片段==（每个片段=== 标题 === + 摘要）→ ==制作人员== → ==画廊== → 导航 → Category

### 卷页面
- 模板：`{{卷资料}}`
- 导航：`{{卷导航}}`
- 数据源：ISBN、日期等外部信息
- 典型结构：模板 → 简介 → 台版封面图 → 导航 → en链接 → Category

## Slash Command 索引

| 命令 | 用途 | 默认行为 | 破坏性？ |
|------|------|---------|---------|
| `/wiki_test` | 测试 Wiki 连接 | 直接执行 | 否 |
| `/wiki_info [name]` | 查看模板/页面信息 | 直接执行 | 否 |
| `/wiki_convert_page page_name="..."` | 转换单页 | dry-run | 加 `--confirm` 才真改 |
| `/wiki_convert_category category="..."` | 转换分类下页面 | dry-run | 加 `--confirm` 才真改 |
| `/wiki_convert_template template="..."` | 转换模板引用页 | dry-run | 加 `--confirm` 才真改 |
| `/wiki_restore page_name="..."` | 从历史恢复 | 仅列版本 | 加 `--confirm` 才恢复 |
| `/wiki_scan [--limit N]` | 扫描待转换页面 | scan-only | 否 |
| `/wiki_scan_category` | 扫描分类命名空间 | scan-only | 否 |
| `/wiki_fix_links old_text="..." new_text="..."` | 批量修复链接 | dry-run | 加 `--confirm` 才真改 |
| `/wiki_update_cat_refs [categories...]` | 更新分类引用 | dry-run | 加 `--confirm` 才真改 |

### 不可用的命令（用 bash 手动执行）

| 操作 | Bash 命令 | 原因 |
|------|----------|------|
| 批量扫描转换 | `python src/fandom.py scan --approve-all` | blast radius 过大 |
| 移动分类 | `python src/fandom.py move-category "旧" "新"` | 影响范围大 |
